# FileChannel · 文件通道

> 两台电脑之间的**点对点文件通道**：各开一个窗口，把文件 / 文件夹拖进去就发过去，对面会弹出提示，可以选择**接受**或**拒绝**。
> 不需要中转服务器，局域网 / Radmin VPN / Tailscale 都能用；Windows x64，绿色免安装，目标电脑**不需要装 Python**。
>
> 开源许可：[MIT](LICENSE) —— 可自由使用、修改、商用，保留版权声明即可。

```
   我的电脑 (10.20.11.15)                      对方的电脑 (校园网 / VPN)
   ┌──────────────────────┐                   ┌──────────────────────┐
   │  FileChannel 窗口     │                   │  FileChannel 窗口     │
   │  拖文件进来 ──────────┼──── 直连 ────────►│  弹窗：接受 / 拒绝     │
   │  接收目录 ◄───────────┼───────────────────┤  拖文件进来            │
   └──────────────────────┘                   └──────────────────────┘
              一台机器既能收也能发，两个方向互不影响
```

## 这是什么

写这个工具的起因很实际：**一台台式机走网线、一台笔记本走校园网 Wi-Fi，想随手把文件丢过去**。
微信/网盘要么压画质、要么限速、要么得先上传到别人服务器；共享文件夹跨网段又通不了。

FileChannel 的做法是：

1. 程序在两台机器上各起一个**小 HTTP 服务**（默认 TCP `8765`）；
2. 发送方先发一个“我要给你发这些文件”的**请求**（`/offer`）；
3. 接收方**弹窗**显示发送方、文件清单、总大小，人点「接受」或「拒绝」（60 秒不响应自动拒绝）；
4. 接受后才开始**流式传输**（`/upload`，1 MiB 一块），两边都显示进度；
5. 收完的文件放在 `桌面\文件通道接收\<发送方>_<时间>\`。

全程**点对点**，除了系统自带的 Windows 防火墙，没有任何第三方依赖、没有云、没有账号。

## 特性

| 能力 | 说明 |
|---|---|
| 🖱️ **拖放发送** | 从资源管理器把文件 / 文件夹直接拖进窗口，点完立刻开始 |
| 📁 **文件夹直传** | 文件夹按**原目录结构**逐个文件发送（**不打包 zip**）：不占临时磁盘、不受系统盘空间限制、空文件夹也会还原 |
| ✅ **对方确认** | 接收端弹窗列出文件与总大小，可选「接受 / 拒绝」，60 秒倒计时自动拒绝；可勾选“以后自动接受该主机” |
| 📊 **进度可见** | 发送、接收两侧都显示百分比；收完响一声提示，可一键打开所在文件夹 |
| 🧩 **完整性校验** | 以 `Content-Length` 为准逐字节校验，断线/不完整会报错，**不会静默产生半个文件** |
| 🔎 **自动发现** | 同一广播域内 UDP 心跳互相出现（3 秒一次），也可以手动填 IP |
| 🔑 **可选口令** | 两端填一样的口令才允许发送；校园网/公用网络建议开启 |
| 💻 **独立 exe** | 仓库根目录的 `FileChannel.exe` 由 PyInstaller 打包，拷过去双击就能跑 |
| ⌨️ **命令行模式** | `--serve` / `--send`，方便脚本化、无人值守或排查问题 |
| 🧪 **自带测试** | `test_filechannel.py` 10 组自动化测试（含哈希比对、口令、路径穿越、超时） |

## 快速开始

### 方式 A：只想用（推荐）

1. 下载仓库里的 **`FileChannel.exe`**（或整个仓库），两台电脑各放一份；
2. **首次使用**在每台机器上放行端口：右键 [`安装防火墙规则(以管理员运行).cmd`](安装防火墙规则%28以管理员运行%29.cmd) → 以管理员身份运行
   （如果跳过这步，第一次启动时 Windows 会弹“是否允许访问网络”，点**允许**也可以）；
3. 双击 **`启动文件通道.cmd`**（或直接双击 `FileChannel.exe`）；
4. 把对方窗口顶部显示的「本机地址」填到自己窗口的“对方地址”里 → 点 **测试连接**，变成绿色「● 已连接」即通；
5. 点 **记住对方** 起个名字（以后从“常用”下拉框直接选）；
6. **把文件 / 文件夹拖进蓝色区域** → 对面接受后开始传输。

### 方式 B：从源码跑

```bat
git clone git@github.com:ilovedogandcat/file-channel.git
cd file-channel
python FileChannel.py            :: 需要 Python 3.8+（只用标准库 + tkinter）
```

## 两台电脑怎么连通（跨网络方案）

FileChannel 只要求“**对方的 IP 能连上**”，具体怎么打通由你选：

| 方案 | 适用 | 地址长什么样 | 备注 |
|---|---|---|---|
| **同一局域网** | 两台机器在同一网段、且交换机/AP 允许终端互访 | `10.20.11.15` 之类 | 最快，零额外安装；校园网常把有线和 Wi-Fi 隔离，这时用下面的方案 |
| **Radmin VPN** | 免费、装完即用，界面简单 | `26.x.x.x` | 两台机器**创建/加入同一个网络**（网络名 + 密码）即可 |
| **Tailscale** | 穿透性最好（走 443/UDP），跨运营商/严格防火墙首选 | `100.x.y.z` | 两台机器用**同一个账号**登录 |

用法都一样：把对方在这个网络里的地址填进“对方地址”，点 **测试连接**。

> 判断标准只有一个：**测试连接** 变成绿色「● 已连接」。连不上时先看对方窗口底部日志有没有“正在监听 0.0.0.0:8765”。

## 使用方法

### 发送

- 拖文件 / 文件夹到蓝色区域，或点「选择文件…」「选择文件夹…」；
- 一个请求可以带多个文件（拖多个/多选），它们共用一次“接受/拒绝”；
- 文件夹**不打包**：程序只扫描一遍目录（毫秒级），然后按原结构逐个文件发过去，对方收到同样的目录树（空文件夹也会建出来）。

### 接收

- 对方发起时本机会**响铃 + 弹窗置顶**：

  ```
  【台式机】 想给你发送文件
  共 3 个文件，合计 12.40 MB
      报告.pdf      2.10 MB
      数据.xlsx     0.30 MB
      ...
  [✓] 以后自动接受来自该主机的文件        (60 秒后自动拒绝)
        [ 接受 ]        [ 拒绝 ]
  ```

- 文件名会被净化（去掉路径与非法字符），只落在接收目录内；
- 同名文件自动改名成 `xxx (1).pdf`，不会覆盖；
- 接收目录默认 `桌面\文件通道接收`，可在界面里改。

### 界面上的几个字段

| 字段 | 说明 |
|---|---|
| 名称 | 本机显示名（对方弹窗里看到的就是它），点「改名」生效 |
| 本机地址 | 本机所有网卡的可用地址（含 Radmin/Tailscale），点「复制地址」发给对方 |
| 对方地址 / 端口 | 对方的 IP 和端口，默认 `8765` |
| 口令 | 两端一致才允许发送；留空表示不校验 |
| 测试连接 | 立刻握手一次并显示结果 |
| 记住对方 | 存进“常用”，下次从下拉框直接选 |
| 发现 | 同一广播域里跑着 FileChannel 的机器会自动出现在这里 |

## 命令行模式

适合脚本、无人值守，或图形界面出问题时排查：

```bat
:: 接收端（自动接受，落到指定目录）
FileChannel.exe --serve --port 8765 --auto-accept --dir D:\收件

:: 普通接收（每次在控制台问 Y/n）
FileChannel.exe --serve

:: 发送端（文件或文件夹都可以；文件夹按原目录结构逐个文件发送，不打包）
FileChannel.exe --send D:\报告.pdf D:\数据 --to 26.172.14.81:8765 --pin 可选口令

:: 换个端口、改个名字
FileChannel.exe --port 8766 --name 台式机
```

打包成 `--windowed` 的 exe 也能在 cmd 里用：程序会 `AttachConsole` 到父控制台输出进度。

`FileChannel.py` 内部分区（按文件顺序）：

| 区块 | 内容 |
|---|---|
| 工具函数 | 大小格式化、文件名净化、本机 IP/广播地址枚举（含 Radmin/Tailscale） |

| `DropTarget` / `simulate_drop` | 纯 ctypes 实现 Windows 拖放（`WM_DROPFILES`），并支持合成消息做自动化测试 |
| `App` | tkinter 界面：拖放区、发送/接收列表、接受-拒绝弹窗、状态栏、日志 |
| CLI | `--serve` / `--send` / `--selftest-drop` |

## 工作原理与协议

HTTP/1.1，用 Python 标准库自己实现服务端与客户端（`http.server` + `http.client`），不引入任何第三方包。

| 方法 | 路径 | 请求 | 响应 |
|---|---|---|---|
| `GET` | `/ping` | — | `{app, version, name, host, port, pin_required, time}`，用于连接测试和握手 |
| `POST` | `/offer` | JSON：`{from, files:[{name,size}]}`，可带 `X-Pin` | 阻塞等待对方点按钮：接受 → `{accept:true, token}`；拒绝/超时 → `{accept:false, reason}` |
| `POST` | `/upload` | 头：`X-Token`、`X-Rel-Path`（相对路径，URL 编码；兼容旧的 `X-File-Name`）、`Content-Length`；体：原始字节流 | `{ok:true, path}`；token 无效 403、字节数不符报 `incomplete` |

一次发送的完整时序：

```
发送方                                          接收方
  │  GET /ping            ────────────────►   │  确认是 FileChannel、是否要口令
  │  POST /offer (清单)    ────────────────►   │  ① 弹窗给人看
  │                                            │  ② 人点「接受」
  │  ◄──────────── {accept:true, token}       │  ③ 生成一次性 token（30 分钟有效）
  │  POST /upload 文件1    ────────────────►   │  ④ 流式落盘（1 MiB 一块）+ 进度
  │  POST /upload 文件2    ────────────────►   │
  │  ...                                       │
```

几个实现上的取舍：

- **tokens 用 `secrets.token_urlsafe`**，与 offer 绑定，30 分钟过期；没有 token 不允许上传。
- **文件夹直传而不是打包**：只 `os.walk` 一遍拿元数据，逐个文件流式发送，接收端按 `X-Rel-Path` 还原目录。
  好处是零等待、零额外磁盘、空目录也能还原；代价是**不做压缩**（可压缩数据在网线上会变大），且文件很多时请求数多——
  所以发送端复用同一条 HTTP 连接，避免每个文件都重新握手。
- **不做断点续传**：中断就重发。好处是实现简单，坏处是大文件断了要重来——可接受。
- **接收端不落“半个文件”**：先写临时目标文件并逐块校验字节数，不完整就报错（界面上是失败状态）。
- **拖放没用第三方库**：`DragAcceptFiles` + `SetWindowLongPtrW` 子类化窗口过程处理 `WM_DROPFILES`，
  并用 `GlobalAlloc` 拼一个 `DROPFILES` 结构来合成消息，实现全自动的拖放测试。
- **自动发现**：每个网卡算广播地址（含 Radmin 的 `26.255.255.255`），UDP `8766` 每 3 秒发一次心跳。

## 安全说明

- 传输是**明文 HTTP**，设计前提是**在可信网络（局域网 / VPN）内使用**；请勿直接暴露到公网。
- 有 **token 校验 + 人工确认** 两层拦截：别人即使知道你的 IP，也必须你点「接受」才能进来。
- **文件名净化**：`../../evil.txt` 这类名字会被削成 `evil.txt`；文件夹传输的每级路径都会单独净化，绝对路径和 `..` 直接丢弃，最终还会校验落盘路径必须在接收目录内（有两条自动化测试覆盖）。
- **口令是可选的**：在校园网、宿舍网这类环境建议两端都设一个；口令以明文头传输，只防误接入，不防抓包。
- 若将来要跨公网，建议改为走 Tailscale/WireGuard 之类的加密隧道，或给 `/upload` 加 TLS 终止。

## 自己构建

```bat
:: 1) 直接跑源码
python FileChannel.py

:: 2) 打包成单文件 exe（约 11 MB，目标机器免装 Python）
python -m pip install pyinstaller
python -m PyInstaller --noconfirm --clean --onefile --windowed --name FileChannel FileChannel.py
:: 产物：dist\FileChannel.exe
```

> 注意：PyInstaller `--onefile` 会先起一个父进程（bootloader）再起真正的子进程，
> **主窗口属于子进程**；用 `Get-Process` 看父进程会误以为“没有窗口”。

## 自动化测试

```bat
python test_filechannel.py
```

覆盖 10 组场景（全部通过）：

| # | 场景 | 断言要点 |
|---|---|---|
| 1 | 一个请求发 3 个文件（5 MB / 1 KB / 3 MB） | 3 个文件都到，**逐个 SHA-256 比对一致** |
| 2 | 对方点“拒绝” | 发送方得到失败结果，接收端**不落盘** |
| 3 | 口令校验 | 口令错被拒（403）；口令对可发送且内容完整 |
| 4 | 恶意文件名 `../../evil.txt` | 被净化，且**只能落在接收目录内** |
| 5 | 发文件夹（含子目录、空目录、1 MB 文件） | 接收端**目录结构原样还原**、空目录也建、接收端**没有 zip** |
| 5b | 相对路径里塞 `../../evil.txt` | 被净化，仍然只落在接收目录内 |
| 6 | 伪造 token 上传 | 403 拒绝 |
| 7 | 故意只发一半字节 | 服务端识别 `incomplete` |
| 8 | `/ping` 与 UDP 自动发现 | 认出对端程序、发现报文能被接收 |
| 9 | 命令行 `--send` | 退出码 0，文件完整送达 |
| 10 | 对方一直不点按钮 | 到时间返回超时，不会永久卡住 |

```bat
FileChannel.exe --selftest-drop out.json 文件1 文件2
```

## 常见问题

| 现象 | 处理 |
|---|---|
| **测试连接** 连不上 | ① 对方程序是否在运行（日志有“正在监听 0.0.0.0:8765”）；② 地址/端口对不对；③ 两台机器是否在同一网络（见[跨网络方案](#两台电脑怎么连通跨网络方案)）；④ 对方防火墙是否放行（跑一次 `安装防火墙规则(以管理员运行).cmd`，或首次启动时点“允许访问”） |
| 提示端口被占用 | 已经开了一个副本，关掉旧的；或启动时换端口：`FileChannel.exe --port 8766` |
| 对方没弹窗 | 看双方日志：若对方显示“收到来自 … 的请求”，说明网络通了，只是弹窗被挡住（弹窗会自动置顶 + 响铃） |
| 传输速度慢 | 走 Radmin/Tailscale 会受中转影响；同一局域网直连最快 |
| 传大文件夹会不会先压缩很久？ | 不会。文件夹是**直接按目录结构传**的，只扫描一遍目录（毫秒级），不打包、不占临时磁盘；代价是**不做压缩**，纯文本/日志这类数据在网上会比压缩后大一些（照片、视频本来压不动，没影响） |
| 文件夹里的空目录会丢吗？ | 不会，`/offer` 里会列出空目录，接收端先建好目录结构 |
| 想恢复默认设置 | 删掉 `C:\Users\<用户名>\.file_channel\config.json` |
| 想彻底不用图形界面 | 用 `--serve` / `--send`（见[命令行模式](#命令行模式)） |

## 更新记录

### v1.1
- **文件夹改为按目录结构直传**（不再打包 zip）：点完立刻开始，不再占用系统盘临时空间，空文件夹也能还原；
